# R.2 — F-013: Prep-min inconsistente entre vitrinas

- **Verdict:** CONFIRMADO (minor, mismo dato, tres renders)
- **Fecha:** 2026-09-11 · Rama: `develop` (solo lectura; sin cambios de código)

## Comando

```bash
sed -n '380,395p' apps/frontend/src/app/public/ecommerce/components/storefront/storefront.component.ts
rg -n "preparation_time_minutes" apps/frontend/src/app/private/modules/ecommerce/components/product-card/product-card.component.ts apps/frontend/src/app/private/modules/ecommerce/pages/product-detail/product-detail.component.ts
```

## Salida

1. Storefront `prepMinutesFor` (L386-394): valida finito, `<= 0 → null` y
   aplica `Math.floor(minutes)`. Con 0.5 → `Math.floor` = 0 → el `@if (...;
   as prepMinutes)` lo oculta (0 es falsy): no se pinta nada.
2. Product-card (L165,169) y product-detail (L165,171) —nótese: viven en
   `private/modules/ecommerce`, no en `public/`: `(p.preparation_time_minutes
   ?? 0) > 0` y pintan el crudo `~{{ ... }} min`. Con 0.5 muestran "~0.5 min".
3. Mismo dato, dos decisiones de render opuestas para el sub-1-minuto.

## Veredicto

CONFIRMADO. Fix según directiva: extraer helper compartido (el de storefront
ya existe y es el más defensivo: finito + `> 0` + floor) y reusarlo en
card/detail + spec.
