# R.1 — F-006 Listener PQR no matchea roles canónicos → CONFIRMADO (minor)

## Comandos

```bash
sed -n '296,302p;243,254p' apps/backend/src/domains/support/pqr/pqr-notifications.listener.ts
grep -n "name: { in:" apps/backend/src/domains/support/pqr/pqr-notifications.listener.ts
grep -n "where: { name:" apps/backend/prisma/seeds/users.seed.ts | head -3
grep -n "roles: { name:" apps/backend/src/domains/organization/roles/roles.service.ts
```

## Salida

```text
# notifySuperAdminsOfResponse (rama response_sent) — literal exacto mayúsculas:
user_roles: { some: { roles: { name: 'SUPER_ADMIN' } } },
# rama store de response_sent — solo literal mayúsculas:
some: { roles: { name: 'STORE_ADMIN' } },

# handlePqrCreated (mismo archivo, fix ya aplicado) — ambos casos + owner/admin/manager:
name: { in: ['super_admin', 'SUPER_ADMIN'] },
name: { in: ['owner','admin','manager','STORE_ADMIN','store_admin','ORG_ADMIN','org_admin'] }, (×2)
name: { in: ['owner','admin','ORG_ADMIN','org_admin'] },

# Canónico (seed + servicio):
users.seed.ts:50:    where: { name: 'super_admin', organization_id: null },
roles.service.ts:830:      where: { roles: { name: 'super_admin' } },
```

## Veredicto

**CONFIRMADO.** `notifySuperAdminsOfResponse` matchea `'SUPER_ADMIN'` exacto pero el canónico es `'super_admin'` minúsculas (seed + `roles.service.ts`); en Postgres `=` es case-sensitive → los avisos de respuesta a superadmins no matchean a nadie. La rama store de `response_sent` solo matchea `'STORE_ADMIN'` mientras `handlePqrCreated` del mismo archivo ya usa la lista amplia (`owner/admin/manager` + ambas cajas) — inconsistencia interna probada.
