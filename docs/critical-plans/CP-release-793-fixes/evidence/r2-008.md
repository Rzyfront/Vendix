# R.2 — F-008: Threshold cero cambia envío gratis en filas existentes

- **Verdict:** CONFIRMADO (minor, comportamiento real sobre datos existentes)
- **Fecha:** 2026-09-11 · Rama: `develop` (solo lectura; sin cambios de código)

## Comando

```bash
git diff origin/main..origin/develop -- apps/backend/src/domains/store/shipping/shipping-calculator.service.ts | rg -n "threshold"
git show origin/main:apps/backend/src/domains/store/shipping/shipping-calculator.service.ts | rg -n "threshold"

```

## Salida

```diff
-      // Free shipping threshold override (common in flat/weight strategies)
-        rate.free_shipping_threshold &&
+        rate.free_shipping_threshold != null &&
+        Number(rate.free_shipping_threshold) > 0 &&
         cartTotals.totalPrice >= Number(rate.free_shipping_threshold)
```

`origin/main` (línea 186): `rate.free_shipping_threshold &&` — el campo Prisma
`Decimal` es un objeto y por tanto truthy incluso valiendo 0; con threshold 0 la
comparación `totalPrice >= 0` siempre es cierta y el envío salía gratis.

`develop` (líneas 212-214): exige `!= null && Number(...) > 0`. Las filas ya
guardadas con threshold 0/negativo dejan de regalar el envío.

## Veredicto

CONFIRMADO. El cambio de semántica sobre filas existentes es real y coincide con
lo descrito en el finding y ADR-04. Pendiente pre-release (no ejecutable desde
aquí, sin acceso a prod): `SELECT id FROM shipping_rates
WHERE free_shipping_threshold <= 0 AND is_active` para inventariar filas legacy.
