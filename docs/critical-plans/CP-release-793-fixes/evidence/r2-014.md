- **Verdict:** CONFIRMADO (minor, frágil; no rompe por el DTO)
- **Fecha:** 2026-09-11 · Rama: `develop` (solo lectura; sin cambios de código)

```bash
sed -n '270,290p' apps/frontend/src/app/private/modules/store/settings/shipping/components/add-rate-wizard-modal/add-rate-wizard-modal.component.ts
```

## Salida

1. Wizard (L283): `base_cost: Number(values.base_cost) || 0` — `NaN`/`''`/
   `undefined` colapsan a 0 silencioso; sus hermanas de la misma literal usan
   `parseNullableNumber` / `parsePositiveThreshold` explícitos (L270-272).
2. Backend (`shipping.dto.ts:111-113`): `base_cost` es requerido
   (`@IsNumber() @Min(0)`, sin `@IsOptional()`), así que el 0 silencioso pasa
   la validación: no hay 400 ni corrupción, pero un tipeo inválido se vuelve
   "gratis" en vez de error visible.

## Veredicto

CONFIRMADO como fragilidad menor sin ruptura. Fix según directiva: misma línea
que el resto del método (parse + error visible si no es número).
