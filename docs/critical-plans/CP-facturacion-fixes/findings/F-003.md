# F-003 — checkout-web-sin-idempotencia

- **Scenario:** double submit / retry creates two orders; each gets its own draft + number (compounds
  F-001). Emptied cart stops naive retries but not parallel/guest ones. No `Idempotency-Key` handling.
- **Proposed fix:** accept `Idempotency-Key` on web checkout; 24h window keyed by (store, cart/user,
  address-hash); second hit returns the first result, no new order/invoice.
