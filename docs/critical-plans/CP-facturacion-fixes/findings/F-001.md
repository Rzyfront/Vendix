# F-001 — quema-consecutivos-en-ordenes-impagas

- **Scenario:** web checkout creates order (`pending_payment`) → `createInvoiceIfConfigured` →
  `createFromOrder` → `generateNextNumber` consumes consecutive under lock. Transfer never paid or
  checkout abandoned ⇒ draft holds a reserved number forever (no `pending_payment` expiry job).
  Finite DIAN ranges exhaust; gaps need justification.
- **Proposed fix:** ADR-01: number at validate/send, never at creation; grandfather numbered drafts.
- **Resolution:** fixed on branch fix/CP-facturacion-fixes, evidence in log/execution.md
