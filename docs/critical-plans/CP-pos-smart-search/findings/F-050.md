# F-050 — Orden deploy código-vs-migración sin fijar

- **Scenario:** Release con `searchIdsRanked` despliega antes de M1 (o migrate aún corriendo): si el path B es alcanzable por default/mis-toggle, todo search 500ea hasta que M1 aterriza. Código-viejo+DB-nueva es seguro pero nadie lo declara; cada deployer improvisa el orden más riesgoso.
- **Proposed fix:** Fijar en C.1: migraciones antes que deploy, código con TRIGRAM default-off + capability guard (F-049) de backstop; mid-migración sirve código viejo + cambios aditivos (no rompen queries viejas).
