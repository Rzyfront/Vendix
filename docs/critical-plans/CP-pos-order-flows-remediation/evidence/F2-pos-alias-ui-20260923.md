# F.2 — POS alias con envío, frontend (2026-09-23)

Los tres gates de cliente formal para `home_delivery` dejan pasar una venta identificada por alias. El shell valida alias no vacío; el paso Envío recibe ese alias, muestra nombre de referencia y entrega `shipping_address_snapshot` con texto, teléfono y coordenadas; para alias **no** hace POST separado de dirección ni manda un `shipping_address_id` viejo. El backend crea la fila y FK dentro de su transacción (ver `F2-atomic-alias-runtime-20260923.md`). El camino de cliente registrado mantiene su libreta y su `is_primary`.

El primer lote Angular **74/74** pasó, pero Playwright sobre `https://vendix.com/admin/pos` detectó una regresión real: botón alias habilitado, clic revertido de inmediato a «Con Cliente» por un `effect` que aún prohibía alias en delivery. Se añadió prueba de clic renderizado que falló antes del fix y se quitó solo esa rama del efecto; el anonimato puro sigue bloqueado para envío. Angular focalizado posterior **76/76**, `ng serve` watcher OK, web HTTP200, cero errores JS.
