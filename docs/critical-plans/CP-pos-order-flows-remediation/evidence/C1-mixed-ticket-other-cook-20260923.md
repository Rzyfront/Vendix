# C.1 — entrega individual en ticket mixto con turno de otro operador (QA local)

Tienda #10, 2026-09-23. Producto preparado #333 sin receta ni stock (`track_inventory=false`) se asignó **temporalmente** a Barra #7 mediante API oficial; se abrió mesa #26/sesión #122/orden #1184 con el mesero #241. `POST /table-sessions/122/add-items` creó dos líneas separadas del **mismo producto**: #1907 `is_takeaway=true` y #1908 `is_takeaway=false`. `POST /kitchen-fire` 201 creó **un** ticket mixto #108 para ambas líneas, inicialmente `pending`, COGS 0, cero movimientos de inventario. Se restauró el producto #333 a `kds_id=NULL` inmediatamente después del fire; el ticket retuvo su estación snapshot #7.

Antes de marcar listo, el mesero probó `PATCH /table-sessions/122/items/1907/deliver`: **409 `ORDER_ITEM_NOT_DELIVERABLE`**, ninguna línea entregada. El cocinero #242 abrió oficialmente turno Barra #43 (201), marcó ticket #108 `ready` (201) y mantuvo su turno **abierto** mientras el mesero usó la página real `https://vendix.com/admin/restaurant-ops/tables/session/122` en Playwright Node. Había dos botones «Marcar entregado». Se pulsó únicamente el de la fila **«Para llevar»**: red `PATCH /table-sessions/122/items/1907/deliver` **200**, toast «Item marcado como entregado», **0** errores JS. No hubo llamada al endpoint de entrega del KDS ni 403 por turno ajeno. La fila #1908 de mesa conservó su propio botón.

SQL inmediatamente después del clic: #1907 `delivered_at=2026-09-23 13:01:53.099`, `delivered_by_user_id=241`, `kitchen_ticket_items.status=delivered`; #1908 `delivered_at=NULL`, `kitchen_ticket_items.status=ready`. El ticket #108 siguió `ready` porque una línea seguía pendiente de servicio. **Exactamente una** línea recibió el hecho de entrega. Los dos `is_takeaway` persistidos conservaron `true/false`; el conteo global de la tienda pasó de false=937/true=29 (antes de este fixture, evidencia C.4) a false=939/true=30 (otro QA no relacionado agregó una línea false); el endpoint no hizo UPDATE a ese booleano. Cero `inventory_transactions` para ambas líneas.

**Defecto de UI detectado y corregido durante el recorrido:** tras el HTTP200 la pestaña «Entregados» contaba 1, pero la fila #1907 aún mostraba «Listo» y «En cocina» contaba 2, porque `kitchenStatusFor` daba precedencia al mapa KDS `ready` obsoleto sobre `order_items.delivered_at`. Prueba Angular roja: `ready` en vez de `delivered`, 2 en vez de 1; arreglo: `delivered_at` gana sobre KDS/SSE; pruebas **6/6** verdes y watch frontend OK. Recarga Playwright real: #1907 **«Entregado · cocina»**, «En cocina» **1**, «Entregados» **1**, #1908 **«Listo»** con botón, sin errores JS. Capturas locales `/tmp/c1-mixed-before.png`, `/tmp/c1-mixed-after.png` y log `/tmp/c1-ui-after-fix.log`.

Limpieza: cocinero cerró turno #43 (201) y mesero cerró sesión #122 (201); mesa #26 quedó `cleaning`, producto #333 con `kds_id=NULL`. Las líneas y ticket QA permanecen como historial local, sin stock. Queda abierto el **estado propuesto de ADR-06** y el barrido global de invariantes DB-08/DB-23; este fixture prueba el carril local, no todas las filas históricas.
