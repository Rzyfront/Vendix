# A.1 — guardar borrador de envío en POS → reabrir → actualizar → cobrar

Playwright standalone sobre `vendix.com` local (MCP browser no disponible), tienda #10, 2026-09-23. **Este sí recorre la creación inicial por UI**, a diferencia de `A1-reopened-ui.md`.

1. POS: agregué producto #302 Coca-Cola 400ml, sin asignación fiscal; checkout eligió «Enviar a domicilio», cliente existente Maria Ulloa (#197), método activo «Entrega Rápida Local» (#9) y su dirección guardada #489. «Guardar borrador» llamó `POST /store/payments/pos` → **201**, orden #1153 / `POS-2026-0339`, `state=draft`, `delivery_type=home_delivery`, dirección FK #489, método #9, $38.000. No creó pago al guardar.
2. Reabrí el draft en `/admin/pos?editOrder=1153` (la acción «Modificar Orden» del detalle había sido verificada en la orden #1150 y navega a esa ruta). El carrito restauró producto, cliente y envío. Recorrí Entrega → Cliente → Envío → Cobro y pulsé «Actualizar»: `PUT /store/orders/1153/editor` → **200**. Este paso ejecutó el editor, pero **no alteré cantidad/precio**; no afirmo prueba de cambio de valor de línea.
3. El CTA pasó a «Finalizar venta». `POST /store/payments/pos` → **201**, confirmación visible (`A1-ui-saved-reopened-paid-1153.png`). No apareció `flow/cancel` posterior. SQL: la **misma** orden #1153 quedó `processing`, `grand_total=38000.00`, `total_paid=38000.00`, `shipping_address_id=489`; pago #837 `succeeded` con `order_id=1153`. Una orden y un pago para ese ID; no segunda orden. El IVA quedó $0, coherente con el producto taxless y el arreglo de fase H.
4. Fiado adoptado con cuotas por API adicional: draft #1154 de $1.500 → `POST /store/payments/pos` con `order_id=1154`, `credit_type=installments`, 2 cuotas mensuales sin interés → **201**, misma orden `pending_payment`, `remaining_balance=1500.00`, cuotas #1/#2 de $750 cada una, una CxC abierta, cero pagos. Replay → **409 `POS_DRAFT_DUPLICATE_ORDER_001`**, sin duplicar cuotas, CxC ni pago. Es QA local, no se canceló: el flujo de cancelación de crédito actualmente deja CxC abierta (hallazgo registrado aparte).

Tests: checkout-shell 38/38, cart 30/30, shipping-step 18/18, error-messages 16/16, PaymentsService 106/106, PaymentsController 9/9. La rama de snapshot-only sin FK sigue abierta bajo ADR-05/F.2. La consulta global DB-02 aún detecta sobrepagos históricos de otras órdenes; esta evidencia no la declara saneada.
