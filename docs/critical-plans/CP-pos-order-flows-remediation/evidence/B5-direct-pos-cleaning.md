# B.5 Aviso desde selección de mesa en checkout POS

Mesa QA #19 creada en `cleaning`. En `https://vendix.com/admin/pos` se eligió producto 302 y «Consumo en mesa» → mesa #19 → alias → efectivo. Network `POST /api/store/payments/pos` respondió HTTP **201**, orden #1129/pago #825, `data.previous_table_status="cleaning"`; no rechazo ni confirmación extra. La UI mostró toast naranja **«Esta mesa estaba en limpieza. Verifica que esté lista para atender.»** mientras el modal indicaba venta completada (`B5-direct-pos-cleaning-warning.png`). SQL confirma mesa ocupada, sesión pagada/abierta y un pago succeeded; el aviso no bloqueó el cobro. El alias del tiquete seguía incorrecto en esta captura porque el contrato backend aún no lo devolvía; se corrigió/verificó después en `POS-alias-receipt-after.*`.
